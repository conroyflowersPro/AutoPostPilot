## Who it is for (and whether “later, other creators” changes design)

**Now:** personal tool. One operator, one X account, one voice.

**Later:** other creators are possible, but that possibility must **not** reshape v11.

It would hurt the product if we generalized now:

- Seed / post prompts written for “any creator”
- Multi-tenant auth, onboarding, generic DNA schemas
- Softened authenticity so the engine is “reusable”

It does **not** require extra architecture if we keep one existing seam:

- Runtime identity stays `@Seung4680`
- Creator DNA + interest areas + writing rules stay **data**, not a SaaS product
- When/if another creator appears, the extension point is a new DNA profile — not a rewrite of the weekly engine

v11 rule: **optimize for this one writer.** Do not add abstraction “for later.”

## What v11 does

Four stages. Nothing else is the product.

| Stage | Job | Who |
| --- | --- | --- |
| **SEED** | Infer concrete subjects inside the creator’s interest area | Grok 4.6, under rules |
| **WRITE** | Turn a seed into a post `@Seung4680` would actually publish | Grok 4.6, under rules |
| **SCHEDULE** | Pick date and spacing from X-algorithm evidence; hand off to Fedica | System + Fedica Publishing API |
| **LEARN** | Published X outcomes update the next week’s seeds and timing | Performance DNA / 14d learning |

### Seed

Sources (both required as inputs, not templates to clone):

1. `@Seung4680` handmade posts (Creator DNA / archive / recent originals)
2. X seeds **inside the user’s interest area** (Tesla/FSD/product observation, daily, gaming, LAFC, and current explicit intent)

Grok 4.6 infers the next concrete subject. Inference has rules. The engine must not emit registry templates, viral clones, or invented firsthand experience as seed bodies.

A seed is a direction, not a finished post.

### Write

Write inside the established rules (Creator DNA, claim/authenticity gates, editorial mode, everyday language, no invented experience).

The post must still pass a human test:

- Not mechanical
- Not a formula with different nouns
- Something `@Seung4680` would send as his own

### Schedule

Publishing provider is **Fedica Publishing API** only.

Date and interval are **not** product-law hardcoded (`17:00` LA + 3h gap + 5/day). Those remain a fallback while X-algorithm timing is incomplete.

Timing must be justified by X distribution evidence for this account (see Open point below). Human `reviewed` gate before Fedica stays unless explicitly revoked.

### Learn

Only **published** posts enter Performance DNA. Drafts and AI text are not success evidence. Learning may advise seed *quality* (entry, wording, media usefulness) and timing windows. It must never clone a winning seed subject.

1. Growth OS, not a viral optimizer.
2. Never invent firsthand experience or current facts without evidence.
3. Strategy is a hypothesis until published X outcomes validate it.
4. REPOST is manual only. REPOST text is not writing voice.
5. Paid/external APIs stay explicit and user-initiated.
6. Publishing failures must not write into Planner Memory / DNA.
7. Inference model for seed and post generation is **Grok 4.6**.

## Open point (needs one answer)

**What is “X 알고리즘에 근거한 날짜와 포스트 간격” as evidence?**

Recommended default (will use unless you override):

- **Primary:** this account’s published-outcome windows from Performance DNA / 14d X evidence, only when confidence is more than a single lucky post
- **Always:** anti-dumping distribution (do not stack posts so X treats them as noise; respect recency)
- **Fallback:** current LA 17:00 / 3h / 5-per-day
- **Not:** generic “best time to post” blog rules, and not cloning another account’s schedule

If this default is wrong, say which of these you mean instead: own-account learned hours, general X ranking practices, or a specific X-algorithm note you already trust.
